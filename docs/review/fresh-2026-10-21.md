## Key findings (settled)

- **A01 P1 Wrong** - Client data export discloses the Artisan Fee. [export.ts:124-139](../../src/domain/data-requests/export.ts) unconditionally selects `artisanFeePercent` for both parties. Call chain: data request -> Admin send-export ([data-requests/index.ts:77-93](../../src/domain/data-requests/index.ts)) -> R2 JSON -> authorized Account `exportFile` -> `routes/data-exports.$requestId.ts`. Issue #111 US161 and the per-viewer decision prohibit a Client seeing the Artisan Fee. Reproduced through the public command path (`fresh-review-export`, see Tests): export JSON contains `"artisanFeePercent": 10` while the ordinary engagement-as-Client projection excludes it. Fix only the role-appropriate export projection; preserve the Artisan's own rate view. Test through request -> `queues.decide` -> `exportFile`, not tables or private `exportOf`.
- **A02 P1 Wrong** - the same export returns every `reviewsReceived` at [export.ts:162-171](../../src/domain/data-requests/export.ts) with no published/revealed predicate. Reproduced: the export JSON contains the pending private review (`rating: 2`, `"Private review pending staff."`) while the ordinary Client job projection has `theirs: null`. Violates US163/US165, Held visibility, and the review double-blind contract. Reuse existing review visibility rules ([reviews/views.ts](../../src/domain/reviews/views.ts), `rows.ts` `isShown`) rather than a second weaker filter. Cover Held, refused, published-but-window-hidden, and revealed cases through the exported JSON.
- **A03 P2 Wrong (static trace)** - [use-action.ts:15-30](../../src/components/use-action.ts) has no `catch`/`finally`: a rejected server function, success callback, or `router.invalidate` leaves `busy=true`, an unhandled rejection, and no fixable error. Manual copies in `home.tsx` (Availability/PassableRow) and the fake-checkout route share it. UI rule requires error states. Preserve typed domain refusals and drafts; add try/catch/finally with a copy-owned retry message; no new Query cache (ADR0017). One browser scenario rejecting an actual mutation asserts a visible retry error, retained input, and a re-enabled control.
- **A04 P2 Partial (traced concurrency gap, not an observed incident)** - [signals/index.ts](../../src/domain/signals/index.ts) `sentBackSignalWrites` reads earlier returned payouts before each commit; [payouts/events.ts](../../src/domain/payouts/events.ts) `payoutStopped` builds those writes before updating its distinct payout. Two simultaneous first/second send-backs can both see no earlier row and never raise the required second-return Signal. Current [signals.test.ts:16-60](../../test/domain/signals.test.ts) is sequential only. Add a deterministic overlapping public `receivePaymentEvent` test before changing code. Preserve the 90-day threshold and no automatic sanction.
- **A05 P2 Needs approval (spec/test discrepancy)** - #111 Testing Decisions says low float pauses the run; Money/Payouts says check float first and unpaid paused items. [payouts/run.ts:34-97](../../src/domain/payouts/run.ts) explicitly sends payouts even when `floatShort` and delegates partial pausing to the fake provider; [payouts.test.ts:618+](../../test/domain/payouts.test.ts) expects that behavior. Do not silently change money scheduling to satisfy one test. A human must settle all-or-nothing pause versus provider-owned pause/partial send. Keep current code during review.
- **A06 P2 Partial (deterministic static contract gap)** - `worker/content-reader.ts` `readPdf` splits successful Markdown on literal `## Contents`/`### Page N` and returns `[]` if absent; `content/check.ts` `readFiles` treats only an EMPTY PAGE as unread, not zero pages - an unreadable/unrecognized PDF conversion can fail open on an otherwise innocent message. The official toMarkdown API promises Markdown data, not these delimiters ([Cloudflare docs](https://developers.cloudflare.com/workers-ai/features/markdown-conversion/usage/binding/)). Default fail closed/Hold; retain the content-reader port; test a zero-page result through public `conversation.send`. No claim a live converter format changed.
- **A07 Partial (central copy)** - #111 Architecture/UI says English copy lives in one place. [src/web/copy.ts](../../src/web/copy.ts) centralizes UI copy, but `accounts/auth.ts:13-18` email subjects, domain refusal strings, and queue labels (`shared/checks.ts`, `data-requests/index.ts` decision labels) are still user-facing static text outside it. Plan one shared static-copy module reachable from domain and web; do not import web into domain, move user-supplied/AI text, or change rule wording. Zero removals promised until key design settles.

Reproduction (A01/A02): the lead-authored test drives only public domain seams - `createHarness`, `given` actors, a full post->quote->hire->work->complete->approve flow, a 2-star pending staff-visible review, an Admin-approved `copy` data request, and `exportFile`. Expected: no `artisanFeePercent` in `engagements[0]` and `reviewsReceived` equal to `[]`. Observed: `artisanFeePercent: 10` present and the pending review present. Source preserved (not executed in-repo) at [fresh-review-export.test.ts.src](fresh-2026-10-21/fresh-review-export.test.ts.src); full output at [fresh-review-export.log](fresh-2026-10-21/fresh-review-export.log) (exit 1).
