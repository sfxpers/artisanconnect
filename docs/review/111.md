- **Done**: the code does it, and a test proves it. A test is a domain test (`test/…`) or a smoke spec (`e2e/…`).
- **Partial**: built, but a test does not prove it, or a part of the story is missing.

- **Wrong**: built against a higher source. That includes cases where a later ADR amendment contradicts #111 and #111 was never edited.

Eight more points surfaced next to the coverage table:

1. **Workers Logs is never turned on.** `wrangler.jsonc` sets only `observability.issues`, so the logs #111 asks for (#208) are not enabled. Cloudflare's docs enable them with `observability.enabled: true`.
2. **Production cannot Hire.** Production runs the fake payment adapter, but the fake checkout page returns 404 there (`src/web/fake-checkout.ts:13`). #111 contradicts itself on this point (see Gaps G6).
3. **`AGENTS.md` points at two files that do not exist:** `.github/workflows/check.yml` and `CODING_STANDARDS.md`. The last audit's commit message says both were added, but they were never committed. Neither was its `docs/review/111.md`. The repo has no CI and no pre-commit hook.
4. **1,012 lines of custom PDF parsing and decryption** exist only to find a script inside a PDF. The spec never asks for that.
5. **#111 has drifted from ADR 0017** on Sentry, TanStack Query, and the Images port. ADR 0017 was amended and #111 was not.
6. **A probe section survives in the tests.** The last audit said probes were gone. One remains, and it keeps `assembleDomain` exported for tests only.
7. **The prompt brief counts "11 other specs"; there are 3.** The e2e folder holds 6 spec files with 8 tests in all, so only `conversation`, `dispute`, and `signals` sit outside sign-up, Hire, and Approval.
8. **The skills match upstream exactly.** All 27 equal `mattpocock/skills` HEAD `49dd158` (2026-10-09). The repo breaks two upstream recommendations: it has no guardrail, and the standards file the reviewer reads is missing.

### 4.1 TanStack Query: in #111, not installed. Is it needed?

**No.** ADR 0017 (amended in `e3ad2f5`) rejects it: "the router's own loader cache covers what the pages need: no data is shared between routes, and every write reloads the page that made it". The code bears that out: every page loads through a route loader, and `components/use-action.ts` (32 lines) calls `router.invalidate()` after each write. Query would add a second cache to keep in step with the loader's.

The fix is to **edit #111's UI-stack bullet** to match the ADR (fix plan item 3). The gap would reopen if a page ever polls, or if two routes share live data. Neither exists today; a Conversation reloads on send.
